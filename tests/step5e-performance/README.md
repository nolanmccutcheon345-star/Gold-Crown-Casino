Run from the repository root:

```sh
node tests/step5e-performance/run.mjs
node tests/step5e-performance/qualify.mjs
```

`STEP5E_PROFILE_SIZES`, `STEP5E_PROFILE_REPEATS`, and `STEP5E_PROFILE_OUT` allow focused diagnostic runs. Qualification expects the complete default matrix with three samples per path and size. The executable uses production recovery APIs, unchanged Step5D archives, independently recomputed BigInt financial totals and full-replay statistics. The bundle/source hash manifest records timing-only instrumentation; no production source is edited.

`evidence/qualification.json` is the final matrix on runtime `398360f`. The fast path now calls the **actual `BrowserPersistence.load`**, including canonical financial bytes, resident hand archive verification, key inventory and the final current-manifest fence. `serialized-idb.ts` models asynchronous requests and atomic publication using JSON strings; it does not model browser disk latency or durability. A lease is pre-acquired for this single-process reference. Full canonical verification, checkpoint installation on an already audited snapshot, and subsequent recovery are separate operations. Optional small-history packing is not part of the separately measured checkpoint-install step. At this sample size p95 and p99 are descriptive maxima, not evidence about rare stalls. Inspector profiles are native Node CPU captures; Node event-loop delay and memory cannot stand in for browser long tasks, INP, UI hydration or physical-device results. Raw CPU profiles include Inspector activation overhead outside the recovery timer; the qualified function summary excludes Inspector frames.

`evidence-initial-retained/` preserves the first diagnostic run. It exposed a harness reference-lifetime problem: an earlier measured return object remained reachable between iterations. The final run explicitly clears those references before collection. Do not use the initial run's memory figures as application retention evidence. The string-backed storage reference intentionally retains all serialized canonical archive bytes; its RSS is not an IndexedDB memory requirement.

The independent hot workload runs with `node tests/step5e-performance/run-hot.mjs`, then `node tests/step5e-performance/qualify-hot.mjs`. It executes 2,000 decisions through the actual controller and `BrowserPersistence`, beginning with the existing 10,000-hand archive, using native hashing and seeded test-only entropy. Every decision checks duplicate preparation; every 250th decision reloads its pending action and rejects a stale duplicate commit. Its final canonical audit and independent financial/statistics comparisons are separate from measured gameplay. `hot-evidence/qualification.json` binds all imported production files to frozen runtime `398360f`. Periodic checkpoint writes and garbage collection account for observed long-tail preparation costs; this does not establish the cause of the earlier untraced 9.79-second sample.

`evidence-a2b9815-partial/` and `hot-evidence-80857d5-partial/` are preserved, superseded diagnostics. Those versions measured checkpoint reconstruction directly and omitted additional checks performed by the actual browser persistence layer. Their numbers must not be presented as complete playable-state readiness. Historical receipts retain their original runtime path labels; compiled artifacts are kept in the corresponding diagnostic directory.
