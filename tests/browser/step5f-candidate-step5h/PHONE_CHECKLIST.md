# Physical phone check — record what actually happens

Use the **isolated candidate URL** supplied with the test package, not the public Version 7 site. Confirm its source/build proof. Do not erase or migrate your ordinary guest save. Guest browser data can be lost if the browser evicts it or you delete site data; this test does not guarantee permanent storage or cross-device sync.

Before starting, record: phone model, OS version, Safari/browser version, source commit, bundle hash, viewport/orientation, text zoom, battery/power mode and saved-hand count. Set hardware to **Physical device** only when using the actual phone. Keep the same complete run URL for recovery.

1. **Open and recover.** Open as a guest. Record shell/loading time and when the app says the save is ready. No betting or cashout should be enabled before financial verification. Save an observation file after startup.
2. **Set up a table.** Use $1/$2 with a $200 buy-in and a mixed known/Unknown lineup. Play complete hands at 2, 6 and 10 seats; also check 9 seats. Record actual names/positions, Hero at bottom, readable cards/stacks/pots and accessible controls. Check portrait, landscape and enlarged text. Record overlaps or unwanted horizontal scrolling.
3. **Bet deliberately.** Before acting, say the call amount, minimum raise, raise-to total and additional chips. Use a size shortcut, edit it and commit with the action button. Test a below-minimum proposal without committing a different action. Record each intended versus actual action, rejected input, accidental double tap and resulting public state.
4. **Finish and cash out.** Open New Session during a hand, read the explanation and use Finish Current Hand / End Session. After settlement, check one cashout and preserved history. Start another session at different stakes/seating. Record wallet, table chips, completed profit and history count before/after; manual wallet adjustments must not become poker profit.
5. **Recover an interruption.** Save an observation file, then reload during a hand. Compare visible bankroll, table state and history after recovery. Separately close/reopen the same candidate URL during a pending bot move. Record the actual mechanism and timing; a reload is not an OS-kill test. Export before and after; report uncertainty if the exact boundary was not captured.
6. **Export history to Files.** After a completed hand, use the app's ordinary History export. Try Share → Save to Files, or Download JSON, then the app's View/copy fallback if necessary. Open the saved file in Files/text viewer. Record its filename, bytes, valid JSON, number of hands and whether only permitted completed-hand cards appear. Import it as a **Study copy** with the rights confirmation; wallet, results and canonical history must remain unchanged. Keep the actual exported file as evidence.
7. **Play an extended session.** Record the true duration and completed hands. Save separate observations for active play, history browsing, audit and reload. Keep slow samples and error counts. Do not call unsupported iPhone heap/Long Task APIs zero; record **NOT_MEASURED**. Intentional think time is separate from preparation.
8. **Send observations for review.** Complete the device form with PASS/FAIL/BLOCKED per actual task, issue steps and screenshots/recordings when available. Save the diagnostic observation JSON separately from the app's history export. No automatic acceptance PASS follows.
