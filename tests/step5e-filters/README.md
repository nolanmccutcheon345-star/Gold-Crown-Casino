# Step5E cash-result filters

Cash component of R1M05: completed canonical cash results can be filtered by session and by the actual small/big blind pair on each hand. Existing `deriveCashStats` remains the calculation authority; mixed-stakes BB/100 uses each hand's big blind, eligible-opportunity denominators and uncertainty remain intact, and imports/ledger adjustments never become result inputs. Tournament ROI, ITM, finish and fees remain unsupported. This lane does not mark the whole mixed cash/tournament criterion passed.

The UI integration is owned by the root lane. `cashResultsFilterMarkup(data, filter, disabled?)` renders escaped public controls `results-filter-session` and `results-filter-stake`, with `results-filter-disclosure`. It accepts a verified compact snapshot and includes historical stake options from its verified statistics checkpoint. `deriveFilteredCashStats(data, filter, now?)` requires an already verified full canonical archive and rejects compact tails or caller objects without the storage capability. `ALL_CASH_RESULTS_FILTER` selects all sessions and stakes; stake keys are integer-cent pairs such as `100/200`.

The result contains `stats`, `hoursAvailable`, `unavailableSessionIds`, and `disclosure`. A partial session stake selection does not allocate the entire session clock to a subset of hands: aggregate `perHour` becomes null and `hoursAvailable` becomes false. Because the existing `CashStats.activeMs` type is not nullable, its zero value is an internal sentinel in this case. The UI must show an em dash for aggregate time when unavailable and for each session listed in `unavailableSessionIds`. A session selected in full retains its recorded active time, including a running foreground clock. The guard also covers a currently active stake without a completed hand. Complete sessions at other selected stakes do not rescue an aggregate clock containing a partial session.

Execution evidence in `evidence/execution.json` pins both new source files and records actual commands.
